# 전투 마감 독립 회귀 검사 인계

상태: **표본 수정 후 실제 Vulkan 실행 193검사/실패 0 로그를 QA가 직접 확인했다. 별도 툴팁 격리 검사도 194검사/실패 0을 확인했다.** 최초 189검사/4실패는 궁수·저격수에도 허용 코스튬이 있다고 가정한 QA 표본 오류였으며, 지원 조합과 미지원 조합을 분리해 수정했다. 엔진 실행은 메인이 담당했고 QA는 코드·로그·명시한 화면 증거를 검토했다. 이번 상태 갱신은 문서만 변경한다. 전체 최종 게이트와 최종 배포 EXE 60분 검증의 승인을 뜻하지 않는다.

## 직접 확인한 결과

- `runtime/check-combat_polish_v053.log`: Vulkan Forward Mobile 실행 및 `COMBAT_POLISH_V053 checks=193 failures=0`. 기본/전직 외형 검사와 지원 코스튬 검사는 구분한다.
- `runtime/tooltip-probe.log`: `TOOLTIP_PROBE_V053 checks=194 failures=0`. 결과 디렉터리는 `artifacts/tooltip-probe-v053/788079`다. 실제 위젯의 GUI hover로 생성한 내장 툴팁을 루트/서브뷰포트, 1280/1920, 우측/우하단에서 검사한다. `_make_custom_tooltip`을 직접 호출하거나 팝업을 임의 부착해 통과시키지 않았다.
- QA가 직접 본 최신 화면은 `artifacts/tooltip-probe-v053/788079/root-1920-ActionCircle-bottom-hover.png`다. 긴 설명과 팝업 전체가 화면 안에 보이는 것을 확인했다. 나머지 모든 PNG를 직접 시각 검수했다고 주장하지 않는다.
- 최초 툴팁 172검사/32실패에서는 논리 좌표와 물리 해상도 혼동 및 자식 뷰포트에만 입력을 주입한 도구 전제를 수정했다. 최신 검사는 명시적 1:1 좌표계와 루트 GUI 입력 전달을 사용한다. 실제 게임의 1600×900 확대 HUD 전체나 외부 운영체제 팝업 검증으로 확대하지 않는다.

## 실행

저장소 루트에서 엔진을 사용하는 다른 검사와 겹치지 않게 실행한다.

```powershell
python tools/run_hidden_check.py combat_polish_v053 graphics
```

종료 코드 0, 로그의 오류·경고 없음, `COMBAT_POLISH_V053 checks=N failures=0` 완료표식, 새 `artifacts/combat-polish-v053/<실행ID>/report.json`의 빈 failures를 함께 확인한다. 파싱/실행 실패는 미통과이며 예상 검사 수를 대신 기입하지 않는다. 전체 게이트에 넣을 때 `godot_test_completion.py`의 `_PLAIN` 목록과 `verify_v01.py` 그래픽 목록 등록이 필요하다(이 작업에서는 수정하지 않음).

## 자동 검사 범위

- 실제 hit의 정상·처치 이벤트에 표적 ID, 0피해·사망·벽·보스 리셋으로 거부된 타격의 무이벤트/HP 보존.
- 기본 검사·궁수·마법사, 대표 전직 swordsman/sniper/summoner의 공개 행동 경로. 근접 즉시 피해와 원거리 즉시 발사를 구분하고 탄환 도착 후 피해를 확인한다. 강공격은 heavy_begin 후 전투 시계 진행, heavy 해제를 사용한다.
- 기본/전직 reader는 위 6직업 모두 검사한다. 코스튬 reader는 별도 함수에서 명시한 지원 조합만 검사한다: warrior/swordsman의 `mint-hanbok`, mage/summoner의 `amethyst-purple-dress`. 런타임 허용 목록·카탈로그 등록·실제 reader 선택을 먼저 확인하고 코스튬 직접 reader와 Gat 라우팅 결과를 대조한다. `class_matching.json`에는 ranger/sniper 허용 항목이 없으므로 해당 조합은 보고서 `reader_samples`에 `not_applicable`로 남기며 코스튬 검사 PASS로 세지 않는다. 준비 단계 생략과 프레임 5/10 선택만 검증하고 그림의 실제 접촉 의미는 별도로 판단한다.
- 유효 피해 이벤트 전달 후 화면에 없는 표적·처치 표적의 만료, 플레이어 피해의 비적용, 실제 마을 이동의 초기화. 처리 루프를 직접 진행하며 시간 대기나 적 렌더링에 의존하지 않는다.
- 수평·대각선·길이 0인 캡슐 양끝, 고리 내외경의 ±0.02 월드 단위와 정확한 경계 포함. 실제 `draw_area`가 제출하는 폴리곤을 동일 호출의 recorder로 수집해 판정과 비교하고 별도로 Node2D에 렌더한다. 픽셀 단위 곡선 일치나 모든 각도의 수학적 동일성을 주장하지 않는다.
- 실제 게임 SubViewport에서 1280×720/1920×1080 HUD 기술명 위로 허수아비 이름을 겹치게 배치, 그리기 완료 후 이름 가림과 몸체 조준 유지 확인. HUD 컨트롤의 툴팁 문자열 존재 검사.

전용 runtime 저장 디렉터리를 사용한다. 기존 사용자 기록을 fixture로 읽거나 쓰지 않는다. 관찰/실전 성능 측정용 파일이 아니라 합성 경계 회귀다. 음소거한다.

## 캡처 및 수동 미검증

새 실행 디렉터리에 고리 예고, 해상도별 HUD 이름 겹침, 기존 코스튬 접촉 reader 갤러리와 report.json을 저장한다. 파일 생성 성공은 가독성·미술 검수 통과가 아니다.

1. 접촉 갤러리에서 프레임 5/10의 실제 접촉/발사 의미를 판정하고, 기본외형·대표 전직·코스튬에서 입력→준비→접촉/발사→회복의 연속 영상을 별도로 확인한다. 원거리 발사와 적 피격은 다른 시점이다. 피격/회피가 공격 포즈를 우선하는 경우도 별도다.
2. `combat_polish_v053` 자체는 툴팁 문자열 존재까지만 검사한다. 별도 `runtime/tooltip_probe_v053.gd`에서 실제 GUI hover, 내장 팝업 경계, 마우스 이탈 후 해제를 검사해 194/0을 확인했다. 이는 실제 위젯을 격리 배치한 검사이며, 전체 게임 HUD의 확대 좌표계·다른 설명과의 중첩·실제 운영체제 마우스·외부 팝업까지 검증한 것은 아니다.
3. 고리 중심의 실제 채움/대비, 대각 캡슐 끝의 투영, 이름 가림 뒤 기술명 가독성을 캡처로 검토한다. 청음과 배포 EXE 검증은 별도다.

청음, 입력부터 접촉까지의 연속 영상, 최종 배포 EXE 60분 검증은 **미확인**으로 유지한다. 실행 보고에는 실제 렌더러/장치/해상도와 검사 당시 소스 해시를 기록한다. 위의 집중 검사 통과를 Vulkan 전환 전체나 제품 완성도 상승으로 자동 환산하지 않는다.
