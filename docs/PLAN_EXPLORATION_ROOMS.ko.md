# 탐사방과 레이드 전장 개선

상태: 이번 범위 구현·개별 검사·전체 회귀 완료, QA/DB 인계 완료. 전체 회귀 105개 그룹/403826개 검사 PASS. 선택 벤치마크 E01/E02/E03/E06/E08의 첫 구현과 사용자 요청인 던전 구조 재설계를 함께 진행했다. 사용자는 갈림길·순환로가 많은 자유 탐사를 선택했다. 해당 벤치마크 범주 전체와 후속 Stoneshard 항목은 별도로 남아 있다.

이번 범위: 여러 경로가 다시 합류하는 비대칭 일반층, 크기가 다른 구역, 전용 레이드 전장, 적을 정리한 뒤 이용하는 채집·휴식·선택형 제단. 레이드층은 준비 공간·전장에 집중하고 잡몹을 제거했다. 일반층 몬스터 드랍·튜토리얼·마을·100층 진행은 보존한다. 자동 매칭, 아군 AI, 공개 배포, 별도 V06 스프라이트는 범위 밖이다. 귀환 보고와 시설 연구는 후속 단계다.

1. `dungeon.gd`: 일반층 그래프·구역 크기·통로를 재설계하고 레이드층은 별도 세 전장으로 생성한다. 진입·출구는 연결하며 보스 전장 안에 일반 몬스터를 배치하지 않는다. 증거: 다중 시드/100층 도달성·통로 폭·전장 안전 영역 검사. 추가 사용자 승인 없음.
2. `exploration_rooms.gd`, `simulation.gd`: 시드 기반 방 목적, 처치 조건, 채집/휴식/제단 거래를 구현한다. 방장 판정과 개인별 일회 보상, 거리·시야·보관 한도·비용 검사를 적용한다. 증거: 실패 시 무변경, 중복 지급 방지, 두 플레이어 독립 수령 검사. 추가 사용자 승인 없음.
3. 월드 표시·미니맵·짧은 상호작용 UI: 목적 아이콘과 적 수, 명확한 선택 결과/비용을 표시한다. 협동에서 개인 선택창이 월드를 정지시키지 않는다. 증거: 실제 1920×1080 캡처, 원격 요청 및 기존 메뉴 회귀. 추가 사용자 승인 없음.
4. `game_database.gd`, `tools/game_db_rules.py`: 생성 규칙과 방 정의를 동일한 런타임 원본에서 DB로 내보낸다. 증거: `tools/build_database.py`, 데이터 무결성과 원본 해시 비교. QA와 DB 관리에 코드·증거·남은 경계를 전달한다. 독립 QA 결과를 개발자 자체 검사와 구분한다.

검사 명령: 번들 Python으로 `tools/run_hidden_check.py exploration_rooms`, `tools/run_hidden_check.py dungeon_variety_v052 graphics`, `tools/run_hidden_check.py exploration_visual graphics`, `tools/run_coop_check.py`를 실행한다. 관련 기존 검사와 텍스트 인코딩 검사를 추가한다. 테스트를 통과한 범위만 완료로 기록한다.

실행·검증 증거와 QA/DB 인수는 [자유 탐사 던전 인계](EXPLORATION_DUNGEONS.ko.md)에 기록한다. 일반층 격자 인상을 줄이기 위한 곡선 연결, 전용 레이드 3구역, QA 지적에 따른 요청 세대 확인을 계획에 반영했다.
