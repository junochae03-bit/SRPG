# 친구 협동 기반 · 개발 인계

2026-09-12. `feat/v052-adventure-clarity`의 미커밋 개발본. 공개 배포·자동 매칭은 하지 않는다. 방장이 여는 최대 6인 방이며, 방장도 인원에 포함한다. 선택 벤치마크 46개 전체 완료 보고가 아니다.

## 연결된 기능

- 타이틀의 **친구와 모험**에서 마을에 도착한 저장 슬롯으로 방 생성 또는 주소 참가. 게임 중 설정의 **협동 방**에서 참가자와 준비 상태를 확인한다.
- 방장이 월드·피해·보상·거래를 판정한다. 참가자의 캐릭터 ID는 RPC 발신자로 결정한다. 전체 준비 및 모든 참가자의 층 해금 조건을 만족해야 방장이 이동한다. 다운된 사람이 있으면 이동을 막는다.
- 개인 화면은 본인 입력만 멈춘다. 솔로의 메뉴 일시정지는 유지한다. 상태는 초당 10회 압축 전송하고, 채널 간 도착 순서가 바뀌어도 오래된 상태로 되돌아가지 않도록 리비전을 비교한다. 반복 공격은 전체 상태 응답을 별도로 보내지 않는다.
- 타인의 가방·금화 및 개인 전리품은 해당 참가자에게 전송하지 않는다. 보상은 주변 참가자에게 개인별 지급하며 수문장 해금은 파티 전체에 적용한다. 중복 처치·중복 요청은 재적용하지 않는다.
- 참가자마다 방장이 만든 개인 저장 체크포인트를 받는다. 정상 퇴장은 마지막 요청 번호 → 최신 체크포인트 → 디스크 저장 성공 응답 → 퇴장 순서다. 방장 종료도 전원의 저장 응답을 기다린다. 실패·15초 시간초과는 종료를 취소하고 방에 남긴다. 비정상 연결 종료의 저장 실패 기록은 메모리에 보존하고 복구 전 새 캐릭터 생성을 막는다.
- 거래 영수증은 요청 번호와 방장의 성공 응답 및 거래 직전·직후 수치로 표시한다. 스킬 투자·전직·코스튬 구매도 전송만으로 성공 표시하지 않는다. 퇴장 확정 중에는 해당 캐릭터의 새 입력·피해·보상을 막아 최종 저장 이후 진행이 변하지 않게 한다.
- 인원별 체력·무력화 보정은 이탈 시 남은 체력 비율을 유지해 다시 계산한다. 적 수와 공격 피해를 인원에 따라 늘리지는 않는다.
- 협동 다운은 20초, 구조는 거리 1.8 안에서 3초, 구조 후 체력은 35%, 무적은 1초다. 이동·공격·피격으로 구조가 취소된다. 솔로는 기존 안전지대 복귀를 유지한다.
- 레이드 보스는 네 번째 패턴마다 방향이 고정된 돌진을 예고하고, 벽 충돌 시 무력화 빈틈이 생긴다. 소환 효과의 자동 추적·자동 공격은 플레이어 공격·스킬 입력에 반응하도록 전환했다.

## DB 관리 원본

수치의 단일 원본은 `game/scripts/party_rules.gd`의 상수와 `configuration()`이다. 협동 판정은 `coop_session.gd`, 다운·보상은 `simulation.gd`에 있다.

`tools/build_database.py`로 생성한 JSON·SQLite의 metadata에 다음을 넣는다. 기존 테이블 구조와 스키마 5는 유지한다.

- `coop_rules`: 실제 런타임 인원·체력·무력화·구조 수치 및 방 정책.
- `coop_source_rules`: 원본 경로·함수·코드·SHA256. 이동 조건, 요청 처리, 체크포인트, 보상·다운, 이탈 재보정, 구조 틱, 종료 저장 응답 경로를 추적한다.

DB에서 수치를 검토한 뒤 원본을 변경하고 같은 생성기로 재생성한다. 생성 JSON이나 SQLite만 수동 수정하면 게임에 적용되지 않는다. `docs/RUNTIME_FILES.json`은 실제 참조 파일만 기록하며 별도 V06 작업물은 이번 기능에 임의 적용하지 않는다.

## 아직 완료되지 않은 부분

- 다른 가정의 네트워크를 이용한 실접속, NAT 중계·친구 초대, 장시간 지연·손실 환경 검증. 현재는 주소 접속 기반이며 인터넷 접속 편의성까지 완성한 상태는 아니다.
- 끊어진 원정에 재접속, 방장 이전, 일부 인원만 귀환하는 정책. 비정상 연결 손실은 최근 체크포인트 복구이며 통상 2초 간격이다. 정상 퇴장은 최종 디스크 저장 성공 응답을 기다린다.
- 6인 실전 장기 밸런스, 다양한 직업 조합의 플레이 QA, 전체 벤치마크의 탐사·성장·제작·연구·정보 UI 확장.
- QA·DB 관리의 독립 검토와 인수. 생성 및 자체 검사와 독립 승인을 구분한다.

## 독립 검토 반영

DB 관리가 최종 JSON/SQLite·매니페스트·314개 원본 해시와 13개 등록 함수의 일치를 읽기 인수했다. 요청한 `rescale`·구조 `tick` 원본 규칙과 구조 후 무적 상수를 추가했다. QA가 발견한 정상 퇴장 저장 보장(P1), 비동기 스킬 투자 성공 표시(P2), 사적 소지수량 전송(P2)을 수정했다. QA는 해당 수정 경로를 읽기 확인했고, 추가로 발견한 종료 중 신규 참가 P1은 수정 코드와 실제 재현 로그를 직접 확인해 해소 처리했다. 독립 협동 실전 전체 QA 승인을 뜻하지 않는다.
