# 전투 상태의 소유자별 초기화

협동 전투에서 쓰러진 동안 멈춰 있던 연계 유효 시간이 구조 후 다시 살아나는 문제를 수정했다. 쓰러짐과 부활, 파티 이탈이 같은 정리 함수를 사용한다.

- 쓰러진 캐릭터의 직업 자원·연계 시간·임시 강화·보호막·시전·차지·회피 상태를 초기화한다.
- 해당 캐릭터의 대기 공격·투사체·장판·설치 도구·표식·도발을 정리한다. 다른 캐릭터의 대기 공격과 상태는 유지한다.
- 이미 살아 있는 아군에게 전달한 강화 효과는 남은 지속시간 동안 유지한다.
- 패배로 기술·물약 쿨타임을 환급하지 않는다. 구조 시 기존 효과를 되살리지 않고 구조 전용 보호 시간을 새로 부여한다.
- 맵을 이동하면 각 캐릭터의 전투 상태를 새로 구성하는 기존 동작을 유지한다. 캐릭터 저장 형식은 바꾸지 않는다.

협동 프로토콜은 15이며 이전 14의 참가를 거절한다. 정본 DB의 `metadata.combat_lifecycle`에 정책을, `combat_lifecycle_source_rules`에 다섯 소스 규칙을 기록한다.

## 확인 범위

`combat_lifecycle.gd`는 20개 직업의 쓰러짐과 실제 구조 입력, 쿨타임 유지, 동료 상태 분리, 실제 수호 강화 기술, 단독 부활 및 이탈 정리 함수를 검사한다. 적을 제거한 구조 상황을 사용하므로 적에게 공격받으면서 구조하는 난도 검증과는 구분한다.

`combat_lifecycle_network.gd`는 여섯 독립 프로세스와 실제 ENet 스냅샷·게스트 구조 입력을 사용한다. 모든 참가자가 초기 강화, 쓰러짐 후 정리, 구조, 마을 이동을 관찰한다. 일곱 번째 참가 거절과 이전 버전 거절도 확인한다. 시험용 공유 파일에는 단계 관찰 여부만 기록하며 게임 상태를 전달하지 않는다. 맵 이동은 시험 배치를 위한 호스트 함수 호출이며 출발 준비 절차의 검증은 기존 협동 시험이 담당한다.

집중 검사 330개와 전체 검사 164개 그룹 / 541,217개 확인을 통과했다. 정본 DB 임시 재생성 일치 및 DB 관리의 읽기 전용 인수도 완료했다. 기록은 `docs/qa/combat-lifecycle-verification.json`이며 인수 근거는 `docs/qa/team-intake-20260913.ko.md`에 있다.

## 남은 범위

이 변경은 C09 전체 완료가 아니다. 저체력·피격·층당 효과의 모든 조건 조합, 연결 복구와 분리 귀환, 외부 회선의 장시간 플레이는 후속 검증 대상이다. 적의 공유 감속·기절 타이머는 소유자별 상태 항목과 별도로 동작하므로 이번 변경을 모든 군중 제어 효과의 소유권 분리로 해석하지 않는다.

QA팀은 이번 코드에서 추가 확정 결함을 찾지 못했다. 두 시험은 `player_defeated`를 직접 호출하므로 실제 적의 치명 피해부터 쓰러지는 전환을 입증하지 않는다. 이탈 정리 검사는 `reset_after_defeat` 호출 범위이며 갑작스러운 연결 종료 이벤트의 종단 검증이 아니다. 후속 경계 검사에는 실제 치명 공격, 게스트 연결 종료 후 소유자 효과 제거와 동료 상태 유지, 마지막 생존자의 갑작스러운 이탈 시 보스 초기화를 포함한다. QA팀은 엔진을 실행하지 않았고 시험 통과 결과는 메인의 실행 기록을 인수했다.
