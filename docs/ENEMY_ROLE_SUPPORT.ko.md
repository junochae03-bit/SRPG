# 적 무리 편성과 치유 동작

2026-09-13. 적 수를 늘리지 않고 먼저 상대할 대상을 구분하도록 일반 던전의 역할 배치와 치유형 전투를 보완했다. 자연동굴의 장식 밀도와 통로는 그대로 유지한다.

## 편성

각 지역의 기존 출현 후보만 사용한다. 근접 전열과 돌진형, 원거리형과 치유형을 구분하고 해당 지역에 전열·후열 후보가 모두 있을 때 함께 편성한다. 치유형이 없는 생태계에 다른 지역의 치유형을 넣지 않는다. 위험 증원까지 합쳐 방당 치유형은 최대 한 마리다.

이미 생성한 통행 가능한 슬롯에 누가 서는지를 바꾼다. 적 수, 슬롯 집합, 출구 수문장과 레이드 전장은 유지한다. 최초 입구에서 각 슬롯까지의 실제 4방향 보행 거리를 계산해 전열을 가까운 쪽, 후열을 먼 쪽에 둔다. 위험도를 올려도 기본 적의 종류와 자리는 바뀌지 않으며, 추가 적은 별도 증원 슬롯 안에서 배정한다.

이 방향은 **초기 입구 기준**이다. 다른 순환로로 돌아 들어온 플레이어에 맞춰 진형을 자동 회전하지 않는다. 적의 뒤로 접근할 여지를 남긴다. 기존 소음 유인의 파티 공용 4마리 상한을 유지하며, 직접 시야로 마주친 적의 총 전투 인원을 4명으로 제한한다는 뜻은 아니다.

## 치유

| 항목 | 적용 |
|---|---|
| 시전 | 0.9초, 머리 위 초록 십자와 차오르는 원호 |
| 재사용 | 성공 후 6초 |
| 회복량 | 수혜자 최대 체력의 8%, 파티·층 체력 보정 후 계산 |
| 누적 제한 | 수혜자 생존 동안 최대 체력의 24%, 모든 치유자가 공유 |
| 연속 중복 제한 | 회복 직후 3초 동안 같은 대상의 다른 치유 차단 |
| 대상 | 같은 방의 살아 있고 체력이 5% 이상 부족한 적 |
| 제외 | 자신, 다른 치유형, 수문장, 보스, 수련 대상 |
| 거리 | 시전 3.8칸, 부상 아군 탐색 7칸, 자기 최초 위치에서 10칸 이내 |

시전 시작과 완료에 시야·거리·체력·예산을 다시 확인한다. 벽 너머 치유와 만피 대상의 재사용 시간 낭비를 막는다. 남은 회복 예산이 5%보다 작으면 미미한 잔여량만 회복하려고 다시 시전하지 않는다. 소수 체력은 내림하므로 총 회복이 정확히 24%가 되지는 않을 수 있다.

기절과 도발, 치유자 또는 대상의 사망, 유효한 전투 대상 상실, 수혜자 거리·시야 이탈, 위험 장판을 피하는 이동은 시전을 중단한다. 기절·도발이 해당 틱 중 끝나더라도 중단을 적용한다. 중단한 시전은 2초 후 다시 시도할 수 있다. 치유할 동료가 없으면 재사용 시간과 효과음을 소비하지 않는다.

부상 아군이 조금 멀면 보행 속도 내에서 접근한다. 벽을 돌아 다른 방의 아군을 찾아다니지 않는다. 회복 예산은 치유자가 아니라 수혜자에 남으므로 치유자를 교체하거나 잠깐 전투에서 벗어나도 초기화되지 않는다. 새로 생성되거나 튜토리얼 적이 부활할 때만 다시 시작한다.

## 데이터와 검증 범위

관리 DB의 `enemy_support`, `encounter_roles` 메타데이터와 소스 규칙을 갱신했다. 저장된 캐릭터 형식, 아이템 소유권, 접속 프로토콜은 변경하지 않았다. 전투 판단은 기존 방장 시뮬레이션에서 실행하고, 시전 상태는 기존 적 스냅샷으로 전달한다.

모델 검사는 낮은 층·높은 층, 1인·6인 체력 보정, 누적 회복 상한, 시전 중단과 동시 시전을 실제 틱으로 확인한다. 역할 검사는 100개 층과 기본·최대 위험의 200개 생성 사례를 확인한다. 시전과 기절 중단은 실제 게임 렌더러의 1920×1080 캡처로 비교한다.

외부 네트워크 6인 장기 플레이, 직업 조합별 공략 시간과 체감 난도는 아직 확인하지 않았다. 8% 회복량을 최종 밸런스로 확정하거나 C02 전체를 완료로 올리지 않는다. 실행 결과와 정본 인계는 `docs/qa/enemy-role-support-verification.json`에 기록한다.

## 최종 확인

필수 전체 검사 159개 그룹 / 540,511개 확인을 한 실행에서 통과했다. 실행 중 런타임 파일이 바뀌지 않았음을 종료 시 해시로 확인했다. 로컬 6개 ENet 프로세스의 기존 연결·이동·귀환 검사도 통과했으며, 치유형과 6명이 직접 싸운 플레이 테스트와는 구분한다. QA 화면 검토와 DB 관리의 정본 인수를 완료했다.
