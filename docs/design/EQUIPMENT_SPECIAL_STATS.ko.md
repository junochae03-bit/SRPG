# 장비 전용 세부 능력치 8종 인계

상태: 시스템 관리 소유 코드 구현 및 집중 회귀 완료. 메인이 최종 통합·DB 생성·전체 검사·배포를 담당한다. 기존 6대 능력치와 투자/환급 규칙은 보존했다.

수치는 초기 제안값이며 플레이 밸런스 확정치는 아니다. 남은 10종은 V0.7.2 이후 소비 기능 연결 전까지 생성 풀에 넣지 않는다. 궁극기 프로필은 제외한다. 호흡은 적에게 빼앗기는 기력을 줄이지 않으며, 응급은 물약·자연 회복·흡혈·구조 회복에 적용하지 않는다. 보호는 피해 감소율·무적을 늘리지 않는다. 파쇄는 HP 피해·보스 다운 시간·면역 규칙을 바꾸지 않는다.

집중의 백분율 감소 상한은 같은 랭크·직업 패시브 기준 쿨다운에 대해 별자리와 장비 감소를 합쳐 40%다. 랭크 자체의 쿨다운 보상을 원상복구시키지 않는다. 평정은 견고의 일반 경직 감소와 곱연산 후 전체 감소 30% 상한을 적용한다. 기술 회복은 시전자 응급과 받는 사람 활력을 각각 한 번 적용한다.

## 데이터와 호출 계약

- `equipment_special_stats.gd`는 게임 소유자/카탈로그를 가져오지 않는 순수 공용 모듈이다.
- 아이템 필드: `special_stats_version:1`, `special_stats:[{id,points},…]`. 등급별 줄 수 `[0,1,1,2,2]`, 줄당 포인트 범위 `[[0,0],[1,1],[1,2],[1,2],[2,3]]`. 아이템 내부 같은 능력치 중복 금지, 착용 합산 능력치별 최대12.
- `Equipment.make(...,special_options=true)`는 실제 새 아이템의 고유 ID로 한 번 결정한다. 강화 개방 여부와 무관하게 착용 시 즉시 적용한다.
- 제작 견적/DB 정의는 마지막 인수 `false`를 사용한다. 임시 상태는 `special_stats_preview:true`이며 확정 줄을 표시하지 않는다. 최종 ID 지정 후 `Special.generate(item,id)`를 한 번 호출한다. `@` ID는 생성할 수 없다.
- 이미 옵션 또는 버전 필드가 있으면 재생성하지 않는다. 저장·로드·착탈·강화 시 옵션을 다시 뽑지 않는다. 기존 저장에 두 필드가 없으면 그대로 보존하며 소급 생성하지 않는다.
- `Special.valid_item(item)`는 미리보기·알 수 없는 버전/옵션·중복·범위 밖 포인트·소수 포인트·잘못된 줄 수를 거부한다. 인벤토리 견적 검사용 `allow_preview=true`와 실제 저장 검증은 구분한다.
- `sim.recalculate`가 착용 가능 장비만 모아 `p.equipment_special_points` 캐시를 갱신한다. 캐시는 스냅샷으로 전달하지만 저장 권한 데이터는 아니다.
- `effect(p,effect_id)`, `points(p,stat_id)`, `totals(equipped_items)`, `option_text(item)`가 표시·실제 효과에 공통으로 쓰인다.
- `Special.profile`은 기본/전직 스킬의 표시와 실제 시전 값을 함께 처리한다. `stagger`는 타격 예산 생성 시 한 번 적용한다. 도구는 메인이 설치 시 값을 기록하고 발동 때 기록값을 소비하도록 연결했다.
- `Progression.configuration`은 실제 저장 버전8과 활성8종 메타데이터를 내보낸다. 주 능력치 버전2는 유지한다.
