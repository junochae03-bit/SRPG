## 현행 문제와 개선

채집물은 방 중심 좌표에 고정된다. 주변 장식은 3칸 격자에 그림을 순환 배치한 뒤 55%만 무작위로 남긴다. 별도 동굴 장식은 여러 지역에 푸른 광맥 바위를 추가한다. 따라서 보상 오브젝트·자연물·바닥 흔적이 각각 다른 규칙으로 놓여 서로 어울리지 않을 수 있다.

광맥은 암벽의 오목한 부분, 씨앗은 지형의 식생 경계, 상자는 통로에서 비켜난 벽 쪽 빈 공간에 둔다. 작은 배경 소품은 같은 재질·색감으로 2~4개씩 모으고 군집 사이에 여백을 남긴다. 군집에 보상 노드를 추가해 보상량을 늘리지 않는다. 채집물은 낮게, 상자는 광맥보다 작게 표시하는 크기 제안도 proposal.json에 분리했다.

주변 식생 위치는 렌더러 props를 생성기로 역참조하지 않는다. 맵의 지형·지역 테마·독립 시드로 공통 군집 기준점을 정하고, 생성기와 장식 렌더러가 이 기준을 함께 사용해 순환 의존성을 피한다. 실제 art 후보는 기존 LIVE_POOLS 안에서만 고른다. 새 씨앗 재료나 신규 채집 보상을 만드는 변경은 아니다.

## 저장·보상 주의

`expedition_goals.valid`는 현재 challenge를 허용하고 `Simulation.add_player`가 restore를 호출한다. KINDS에서 바로 빼서 기존 저장 전체가 유효하지 않게 되는 방식은 피한다. 구형 challenge 목표만 정확한 기존 형식으로 검증해 읽은 뒤, 활성 목표를 비우고 새 목표 선택을 안내하는 호환 경로를 넣는다. 삭제된 목표를 자동 완료 처리하거나 보상을 지급하지 않는다. 새 선택 요청으로는 challenge를 허용하지 않는다.

exploration_claims/challenges는 현재 생성된 층의 상태이고 persistent에는 목표를 저장한다. 보유 아이템·금화는 보존한다. 생성 배치가 바뀌므로 세션 중간 교체 대신 새 맵 생성 시 적용하고, 필요하면 생성 버전/프로토콜로 옛 좌표 요청을 거절한다. 정책 결정은 메인 저장·멀티플레이 검증과 함께 한다.

삭제에 따른 정수 공급 감소와 중간 회복 제거는 실제 밸런스 변화다. 이를 숨기기 위해 상자 보상·몬스터 드롭을 임의 증량하지 않는다. 이번 사용자 요청에서 회복 재배치나 보상 대체는 확정되지 않았다.

## 구현·검증 순서

1. 삭제 5개의 생성·행동·UI·목표 추천과 구형 목표 호환을 먼저 처리한다.
2. 지형에 맞는 위치 생성과 동일 시드 결정성을 확보한다. 방 중앙으로 무조건 되돌리는 fallback은 금지한다.
3. 배경 군집·종류별 크기·화면 겹침을 조절한다. 동선은 넓게 비우고 채집 지점은 접근 가능한 위치에 둔다.
4. 기존 테스트의 사이트 배열 인덱스를 kind 기반 조회로 교체한다. 5개/레이드1개, room4 휴식, 모든 곁굴 보상 등의 삭제 전 가정을 갱신한다.
5. exploration_rooms/events/challenge/visual, dungeon_exploration_routes, expedition_goals·저장, coop_network, 배경/아트 검사와 DB 생성 검증을 수행한다. 삭제된 동작은 성공 기대 테스트를 단순 삭제하는 대신 위조·구형 요청의 무부작용 거절로 검증한다.
6. 숲1층·동굴11층·포자31층에서 같은 시드·카메라·배율로 전후 게임 화면을 촬영한다. 10지역×여러 시드에서 접근성·발판·입출구·겹침 검사를 넓혀 적용하고, 사용자에게 실제 결과를 보여준다.

완료 기준은 실제 생성·요청·표시에서 삭제 5개가 사라지고, 남는 채집물·상자의 자연 배치가 게임 캡처로 확인되며, 구형 목표 저장과 보상/협동 회귀가 통과한 상태다. 이 문서 작성은 구현 완료를 뜻하지 않는다.
