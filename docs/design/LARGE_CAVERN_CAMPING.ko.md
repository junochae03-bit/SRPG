# 대형 원형 공동·야영·원정 포션 한도

상태: **V0.7.2 첫 개발 범위로 메인에 인계.** 사용자가 원형 공동 방향과 아래 기능을 개발 요청했다. 현재 V0.7.1은 소스 동결 후 검사/빌드 중이므로 이번 작업에서는 문서만 작성했으며 런타임·DB를 변경하거나 엔진을 실행하지 않았다. 메인이 V0.7.2 런타임·UI·DB·회귀 검증을 통합한다. 숫자로 표시한 초기 조정값은 플레이 검증 후 조정할 수 있다.

명시 요청은 큰 원형 공동, 무작위 출구, 다양한 배경, 많은 채집물, 빈 공간의 야영도구 사용, 탐사 휴대 포션 최대5, 회복 역할/난이도 조정이다. **포션 종류 합계5·캐릭터별 적용·초과분 마을 보관·야영 세부 회복량/시간/휴대수는 시스템 관리 제안**이며 사용자 확정 수치와 구분한다. 야영의 후유증 치료 제외는 이전 성당/여관 전용 치료 조건을 보존하기 위한 설계다.

## 확정 의도와 기존 규칙

- 하나의 매우 넓은 원형 공동을 기본 구조로 사용한다. 다음 구역 출구는 무작위 위치에 놓는다. 다양한 바위·배경·채집물을 충분히 배치한다.
- 던전의 빈 공간에서 야영도구를 사용해 야영할 수 있다.
- 탐사 중 휴대 포션은 최대5개로 제한하고 힐러·야영의 중요성과 탐사 긴장감을 높인다.
- 앞선 확정 규칙 보존: 약3초 채집, 근처 적/전투 상태가 채집을 막지 않음, 단순 피격에도 채집 지속, 직접 이동/회피/공격하면 취소. 소음 안내 문구·반경선 없이 실제 배치된 적이 소리를 듣고 접근한다.
- 부활 후 공격/방어 쇠약은 성당, 최대 체력 감소는 여관에서만 치료한다. 야영과 힐러는 이 후유증을 제거하지 않는다.

## 원형 공동 생성

초기 크기 제안은 128~160타일 격자 안의 큰 공동이다. 현재 `dungeon.gd`의 SIZE80/EXPLORATION_SCALE1.6을 단순 확대하는 것에 그치지 않고 하나의 이어진 바닥, 중앙 암반, 주변 작은 암반과 우회로를 생성한다. 실제 바닥 면적과 카메라 이동 중 만나는 대상 빈도로 넓이를 검증한다. 레이드/튜토리얼/마을의 변경은 이 일반 탐사 구조와 분리하여 기존 진행을 보존한다.

큰 중앙 암반과 보조 암반은 이동·시야를 실제로 가린다. 작은 돌, 자갈, 버섯, 뿌리, 광물 조각, 뼈·수레·옛 설비 잔해는 주로 통행을 막지 않는 배경으로 밀도를 만든다. 큰 충돌물 사이 주요 통로는 6인 이동이 가능하도록 넉넉히 확보한다. 예쁜 배경이 채집물·몬스터·공격 예고를 덮지 않게 하며, 통과할 수 있는 장식과 막힌 바위의 표현을 구별한다.

자원은 방 중앙 한 점 대신 바위 가장자리, 벽면, 약초 군락, 옛 작업장에 묶어 둔다. 큰 맵 기준 기본 채집점 40~60개부터 조정하되 실제 이동 중 빈도와 시야 안 밀도를 우선한다. 기본 자원은 풍부하게, 희귀 제작 재료는 일부 노드와 위험/발견 보상으로 유지한다. 기존 모든 채집점에 희귀 보너스를 그대로 곱해 희귀 경제까지 수십 배 늘리지 않는다. 모든 자원 옆에 적을 의무 배치하지 않고 안전한 군락과 위험한 군락을 섞는다.

몬스터는 자원과 겹쳐 균일하게 깔지 않고 서식 무리·순찰·특정 시설 수호 역할을 배치한다. 일부 적은 시야 밖 바위 뒤에서 소리를 들을 수 있는 실제 통로 거리 안에 둔다. 기존 파티 청각 반응 상한4를 유지하며 맵이 커졌다고 주변 무리 전체가 연쇄 합류하게 만들지 않는다. 소음에 반응하는 적을 작업 순간 새로 생성하지 않는다.

### 무작위 출구

원정 맵 생성 시 서버가 시드로 위치를 정하고 해당 맵이 유지되는 동안 고정한다. 공동 가장자리 여러 방위 후보에서 선택하며 매번 정반대편으로 고정하지 않는다. 입구와의 최소 실제 도보 거리(초기 공동 지름의 약35%)와 길 연결을 검사해 바로 옆 출구나 접근 불가능한 출구를 피한다. 출구 앞 상호작용 공간·수호자 공간을 예약하고 장식·채집물·야영으로 막지 못하게 한다. 수호자 처치 등 기존 다음층 진행 조건은 유지한다.

기존 발견/시야 규칙에 맞춰 출구를 발견하도록 하고, 무작위 출구를 미니맵에서 항상 먼저 노출해 탐색 목적을 없애지 않는다. 재접속·세이브 재로드·협동 클라이언트에서 출구 위치와 채집점 ID가 일치해야 한다. 생성 후보 실패 시 검증된 도달 가능 후보를 사용한다.

## 포션 5개와 원정 보급

운영 해석은 **캐릭터당 회복·기력·공격 강화 포션 합계5개**다. 사용자에게 이 기준을 알렸으며 이후 정정 시 변경한다. 야영도구·덫·유인 돌·화염병은 포션이 아니므로 이 합계에 넣지 않는다. `Consumables.MAX_STACK` 하나를5로 바꾸어 모든 도구까지 같은 한도로 묶지 않는다.

마을 보관량과 원정 휴대량을 분리한다. 출발 준비에서 예를 들어 회복4+기력1, 회복3+기력2처럼 선택할 수 있다. 기본 추천 구성은 회복5다. 기존 20개 보유 저장의 초과분은 마을 보관으로 이전해 수량을 보존한다. 처음 접속만으로 자동 삭제하거나 돈으로 강제 환전하지 않는다. 마을 보관품은 던전 가방에서 사용·거래·보충할 수 없다.

출발, 층 이동, 드롭/상자/제조 보상, 협동 거래/공유, 저장·로드 경로에서 합계5를 검사한다. 현재 보유량이4인데 포션2개짜리 보상을 선택하면 비용·개인 claim을 먼저 소비하지 않는다. 수량 분할 회수를 지원하면 한도만큼 받고 잔여분은 별도로 유지하며, 지원하지 않으면 지급 전에 현재 상태를 그대로 보존한다. 야영이 포션을 자동 생성하거나 마을 보관함을 원격으로 열어주지 않는다.

이 한도는 원정 전체 포션 사용 횟수5회가 아니라 동시에 휴대할 수 있는 수량5개다. 탐사에서 얻은 포션으로 다시 채울 수는 있으나 보급 상자·약초 물약 이벤트의 빈도와 양을 조절한다. 잦은 무료 포션 보급으로 제한이 사실상 무의미해지지 않게 한다.

## 야영 초기 규칙

|항목|초기 조정안|
|---|---|
|설치|던전의 걸을 수 있는 빈 공간에서 도구1개 사용, 약3초 설치|
|휴대|캐릭터당 도구2개부터 시작; 포션5개 합계와 별도|
|설치 조건|바닥/자리/거리/통로 확보. 근처 적이나 전투 상태만으로 설치를 거부하지 않음|
|위험|설치·휴식 중 무적 없음. 작업음과 야영 활동은 청각을 통해 기존 적에게 전달|
|회복|범위 안에서 쉬는 각 생존 팀원에게 8초 동안 현재 유효 최대HP의40%와 최대기력의40% 회복|
|회복 예산|캠프마다 팀원별 유한 예산, 한 번 받은 회복은 출입/재접속/휴식 재시작으로 재충전하지 않음|
|방해|이동·공격·회피하면 휴식 회복 정지. 공격받으면 휴식 회복은 정지하지만 설치된 캠프가 사라지지는 않음|
|재개|안전해져 다시 쉬면 남은 예산만 사용. 일반 채집의 피격 지속 규칙과 휴식 회복을 구분|
|수명|초기90초 또는 맵 이동 시 종료. 사용한 도구를 회수해 무한 재설치할 수 없음|
|후유증|쇠약·최대HP 감소를 치료하지 않음. 쓰러진 팀원은 기존 상호작용 구조가 먼저 필요|

위 회복량·시간·휴대수는 밸런스 초안이다. 최대HP 감소 중이면 줄어든 유효 최대HP까지만 회복한다. 캠프는 HP/기력 회복 원천이지 스킬 쿨다운 초기화, 포션 보급, 자동 부활, 디버프 정화 수단이 아니다. 캠프 회복은 장비 응급/약학의 기술·물약 효과와 별도 처리한다.

한 캠프는 파티가 함께 사용할 수 있다. 한 사람에게서 받은 효과를 여러 사람의 캠프로 동시에 중첩하지 않는다. 서버가 설치 비용, 위치, 생존자별 회복 예산, 만료, 중단을 관리한다. 설치 실패/중복 요청은 도구를 추가 소비하지 않는다. 성공한 캠프의 소모와 저장 체크포인트를 연결해 재접속 도구 복제나 설치 전 상태로 되돌아가는 문제를 막는다.

휴식까지 피격 중 강행해야 한다는 추가 사용자 지시가 있으면 이 부분은 별도 조정하되, 현재 사용자 확정인 채집 피격 지속은 변경하지 않는다.

## 난이도 조정 방향

포션 용량 감소와 큰 맵만 동시에 적용하면 힐러 없는 솔로가 먼저 막힐 수 있다. 초기에는 적 HP/공격력을 일괄 상향하지 않고 적 무리 간 간격, 접근 예고, 퇴로, 포션 현장 보급, 야영도구 비용·회복량을 조정한다. 힐러는 이동/전투 중 회복 지속, 야영은 시간·자리·소모품을 쓰는 공동 회복, 포션은 즉각 대응 역할을 갖는다.

현재 `exploration_rooms`는 층마다 화로를 생성하고 `rest`가 HP/기력을 즉시 가득 채운다. 이를 매층 보장된 무료 완전 회복으로 남기면 새 보급 경제와 충돌한다. 일반층 화로를 야영하기 좋은 배경 장소로 전환하거나 제한된 희소 발견으로 조정하고, 레이드 전 준비와 튜토리얼 보호는 별도로 확인한다. 회복 제단·상자2포션·약초3포션 이벤트도 맵 확대 후 실제 빈도를 재계산한다.

검증 파티는 힐러 없는 솔로, 힐러 없는 소규모 파티, 힐러 포함 파티,6인 파티를 포함한다. 같은 진행도의 장비로 출발 자원·캠프 횟수·누적 피해·현장 보급·귀환 시 잔량을 비교한다. 힐러가 있으면 원정을 더 안정적으로 이어가되 없으면 진행 불가능한 필수 직업으로 만들지 않는다. 위험 채집을 선택한 경우와 주요 목표만 찾아 이동한 경우 모두 비교한다.

## 코드 연결과 작업 순서

1. `dungeon.gd`, `dungeon_regions.gd`에 대형 공동 생성/암반 충돌/시야/출구 후보/도달성 확보. `build_encounters`, `encounter_roles.gd`와 청각/귀환 경로의 큰 맵 비용을 검증.
2. `exploration_rooms.generate`의 고정5개와 `room_N` ID 방식을 다수 채집점에 맞게 확장. 같은 방/구역의 여러 노드가 claim ID를 공유하지 않도록 고유 ID 부여. 숨은 방·탐사 목표·시야 스냅샷·상호작용 범위 검증을 함께 맞춤.
3. 포션 목록/원정 합계 한도/마을 보관/출발 보급을 구현. `inventory_model.gd`는 현재 모든 소모품을 공용 MAX_POTIONS로 검사하므로 도구와 포션 집계를 분리. `consumables`, `town_services/operations`, `expedition_brief`, 보상 경로/UI에 같은 공용 계산 사용.
4. 야영의 독립 서버 상태 모듈을 만들고 설치·회복·중단·만료·저장 비용을 연결. 기존 `tactical_tools`의 서버 설치/점유/소모 후 처리 패턴은 재사용하되 덫의 파티상한과 캠프상한을 무조건 공유하지 않음.
5. `local_session.change_map`의 후보 생성→저장 성공 후 적용과 `coop_session` 전환/체크포인트에 휴대·보관 데이터의 원자적 이전 연결. 기존 save8 데이터 마이그레이션, 미지원 버전 거부, 협동 프로토콜 필요 변경은 메인에서 통합.
6. 작업·야영 모션/효과음·남은 회복·휴대5개 표시, 데이터 메타데이터 갱신. 화면에 소음 반경 안내를 다시 추가하지 않음.
7. 회귀·생성 시드 검사·실제 플레이·큰 맵 성능 확인 후 수치 확정. 일반층 생성과 보급 변화의 영향을 받는 기존 검사를 새로운 사용자 규칙에 맞게 갱신하되 저장/원자성/도달성 검사는 완화하지 않음.

## 완료 확인
