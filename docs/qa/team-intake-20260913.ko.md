## DB 관리

대상은 C03 `afecabe`와 C04 `7e44404`다. DB 관리는 변경 중인 작업 파일 대신 각 커밋의 git 객체를 읽었다. SQLite는 메모리에 역직렬화한 뒤 읽기 전용으로 검사했다. 공유 파일 수정, DB 재생성, 엔진 실행은 하지 않았다.

- C03 소스 373개와 런타임 파일 목록 402개, C04 소스 374개와 런타임 파일 목록 403개가 일치했다.
- 33개 테이블의 개수, 전체 SQLite 메타데이터, manifest 크기와 SHA, QA 기록의 정본 SHA가 일치했다.
- SQLite 무결성은 정상이고 외래키 오류는 0건이었다.
- C03 방어 규칙 9개와 C04 조건 규칙 4개의 코드 및 파일 해시가 일치했다.
- 캐시의 압축 payload 해시, 해제 길이, Variant 파싱과 방어·조건 정책 일치를 확인했다. 캐시 전체와 Python 보강 정본 전체의 동일성을 의미하지 않는다.

불일치 0건으로 두 커밋의 DB 인수를 완료했다. 전체 검사 및 로컬 6인 통신 결과는 메인의 실행 기록을 인수한 것이며 DB 관리가 재실행한 결과가 아니다. 진행 중인 C09와 미적용 설계 DB는 이 인수 범위에 포함하지 않았다.
