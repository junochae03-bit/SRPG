궁수·저격수·사냥꾼·탐험가 4종은 모자 아래 실제 정수리가 보이지 않는다. 이 값은 머리 형태를 기준으로 추정했으며 오차 범위를 원본 10px로 기록했다. 그 외는 보이는 머리카락 정수리를 기준으로 약4px의 수동 측정 오차를 허용한다. 모자 아래 픽셀을 직접 측정했다고 주장하지 않는다.

모든 프레임에 같은 몸높이를 적용한다. 웅크림·기울임·발차기·공중동작 때문에 보이는 높이가 바뀌는 현상을 이미지 해상도 변화로 취급하지 않는다. 현재 별도의 프레임별 밀도 보정은 없다. 원화의 포즈별 형태 차이까지 없애는 작업은 아니다.

`reference.foot_local`은 기준0번의 신발 측정 기록이다. 전체 발 궤적 보정은 이 파일의 범위에 포함하지 않았으며,0번에만 피벗을 바꾸면 인접 포즈와 위치가 튈 수 있어 reader에 적용하는 override로 지정하지 않았다.

연결 API: `sprites[id].body_height`를 reader의 기존 `standing_height_estimate` 대신 사용한다. 몸높이 override는 없다. GPU 검수에서 리퍼2번의 낫끝이 지지점으로 잡힌 것을 확인해, 해당 프레임만 `frame_overrides["2"].foot=[103.5,173]`을 기록했다. 신발의 실제 source 바닥은 y256, 가로 지지 범위는 x846..974이다. 직업 alias는 기존 카탈로그를 유지한다.

검증: `C:/Python314/python.exe -X utf8 tools/build_skill_motion_calibration_v06.py --check`는19장 SHA256, 카탈로그 대응, 기준점이 프레임 안에 있고 배경 위가 아닌지, 신발 접점·몸높이의 일치를 확인한다. 메인 reader의 몸높이 연결 후 GPU 갤러리4페이지를 확인했다(`SKILL_MOTIONS_VISUAL_V06_TESTS checks=80 failures=0`). 캡처는 `artifacts/skill-motions-v06-page-0..3.png`. 이 검수에서 확인한 리퍼2번 발 override를 메인 reader에 연결한 뒤 갤러리를 다시 생성했다(80검사/0실패). 16:12 생성된 page2에서 리퍼의 신발이 기준선에 닿고,20px 늘어난 상단 여백 안에 사냥꾼의 귀 전체가 들어오는 것을 최종 확인했다.
