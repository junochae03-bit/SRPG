# DB 관리 절차

게임 세부 정보 DB의 단일 관리 담당은 **DB 관리**다. 스킬·효과·몬스터·드랍·장비·제작·시설·던전·성장과 이후 추가 콘텐츠 및 아트 참조를 포함한다.

DB 관리는 기존 기획·시스템에 맞는 이름, 수치, 조건과 관계를 직접 제안·작성한다. 기록만 모으는 역할로 한정하지 않는다. 설계 제안값·소스 반영값·실행 검증값·배포 반영 상태를 구분하며, 사용자가 맡긴 범위에서는 실행 원본과 관리 DB를 함께 수정하고 검증한다. 현재 캐릭터 조정은 [캐릭터 밸런스 기록](CHARACTER_BALANCE.ko.md)에 있다.

1. 변경 담당자가 DB 관리에 변경 요청을 전달한다. 원본 파일, 고정 ID, 의미·단위·조건, 기존 항목 영향과 아트의 제작/게임 적용 상태를 포함한다.
2. 게임 담당자가 실행 원본을 구현한다. DB 관리는 생성 모델·스키마·참조와 검증 코드를 관리한다. 출력 JSON/SQLite를 손으로 수정하지 않는다.
3. 원본을 확정한 뒤 DB 관리가 canonical 생성·검증을 통제한다. 현재 협업처럼 메인 개발이 Godot를 직렬 실행할 때는 DB 관리와 합의한 동일 원본에서 대신 실행하고 결과를 인계한다. 생성 진입점은 `python tools/build_database.py`; 검사는 `python tools/build_database.py --check`와 관련 DB/게임 회귀 검사다.
4. 인수 기록에는 branch/commit, 미커밋 원본의 SHA-256, 검사 결과, schema_version, JSON·SQLite·schema·manifest 각각의 SHA-256을 남긴다. 원본이 변경되면 재생성·재검증한다. manifest 자체의 해시는 외부 인수 기록에 둔다.

현재 정본 위치는 `D:/SSRPG/publish/SRPG-v04/docs/database/`다. 구버전 `D:/SSRPG/RPG2`는 개발/검증 원본으로 쓰지 않는다. 단, 전달받은 아트팩의 보존 위치로 참조할 수 있다. 사용 전 아트는 별도 인수 목록으로 관리하며 실제 런타임 연결 없이 applied로 등록하지 않는다. 제작 중 자산과 추천 스킬 매핑도 확정 데이터로 취급하지 않는다.
