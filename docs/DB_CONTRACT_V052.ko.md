# V0.5.2 세부 정보 DB 계약안

2026-09-10 · DB 담당의 읽기 조사 초안. 실제 개발 원본은 `D:/SSRPG/publish/SRPG-v04`, 확인한 브랜치는 `feat/v052-adventure-clarity`다. `D:/SSRPG/RPG2`는 구버전이며 이번 작업 대상이 아니다. 이 문서는 DB 전체 관리 범위 중 이번 변경분의 인계 계약이다.

현재 구현 담당자가 소스를 변경 중이다. 아래 관찰값은 릴리스 확정값이 아니다. 이 작업에서는 canonical `docs/database/*`, 게임 코드 수정, Godot 실행, 커밋을 하지 않는다. 구현 담당자가 최종 재생성·검증한 DB와 정확한 해시를 전달한 뒤 관리권을 인수한다.

## 데이터 원칙과 제안 테이블

기존 직업·스킬·장비·몬스터·드랍·별자리·아트 registry를 보존한다. 새 테이블은 제안이며 현재 존재한다고 해석하지 않는다. 생성 원본은 런타임 정의다. 아래 문서 수치를 별도 하드코딩 원본으로 사용하지 않는다.

| 제안 테이블 | 키 및 필수 정보 |
|---|---|
| item_definitions | 기존 아이템 ID, 종류, 이름, 소지 상한·묶음 규칙, 아트 참조 |
| facilities | 런타임 시설 ID, NPC·이름, 위치, 접근 조건, 아트 참조 |
| service_operations | `facility:operation` ID, facility FK, 허용 입력·수량, 선행 조건, 금화 비용/보상 규칙, 성공·실패 정책 |
| service_inputs / service_outputs | operation FK, item FK, 수량 또는 동적 계산 규칙, 소비/생성 구분 |
| service_effects | operation FK, 장비 소비·옵션 변경·회복·의뢰 초기화 등 비아이템 효과와 적용 조건 |
| inventory_rules | 가방 너비·높이·칸수, 물약 상한, 묶음/장착 상태 규칙 |
| dungeon_layouts | LAYOUTS의 문자열 ID, 순서 인덱스, 앵커, 연결, 입구·수문장 인덱스, 통로·방 생성 규칙 |
| encounter_rules | layout FK 또는 공통 정책 ID, 방별 수량 후보, 역할, 배치 형태, 엘리트 방, 몬스터 선택 규칙 |
| training_rules | 수련장 ID, 입장·퇴장·복귀, 표적 능력치·방어·초기화, 보상 제한, 측정 정의 |

동적 계산은 `rule_id`, `source_path`, `source_symbol`, 입력 변수·단위·범위와 함께 수록한다. 공식 문자열만 저장해 실행하지 않는다. 기준 상태를 명시한 평가 예시를 함께 둘 수 있으나 실전 고정값으로 표시하지 않는다. 플레이어의 현재 금화·인벤토리·DPS는 콘텐츠 DB에 저장하지 않는다.

## 마을·제작: 코드에서 확인한 임시 값

원본: `game/scripts/town_operations.gd`, `service_quote.gd`, `town_services.gd`, `inventory_model.gd`.

| 작업 ID | 단위 작업의 입력·비용 | 출력·효과 | 허용 수량 |
|---|---|---|---|
| smith:salvage | 미장착 장비 1개 소비, 금화 0 | 광석 `1+등급*2+강화`; 등급>=2면 정수 `등급-1` | 1 |
| shop:potion | 금화 15 | 물약 1 | 1,5,10 |
| alchemy:potion | 금화 10, 별씨앗 3 | 물약 3 | 1,3,5 |
| alchemy:essence | 금화 40, 별씨앗 5, 광석 5 | 정수 1 | 1,3,5 |
| alchemy:ore | 금화 20, 별씨앗 5 | 광석 3 | 1,3,5 |
| guild:supply | 별씨앗 10, 광석 5 | 금화 300 | 1 |
| guild:cancel | 진행 중 의뢰 필요 | 의뢰·진행도 초기화, 보상 없음 | 1 |
| inn:resupply | `10+15*max(0,물약상한-현재물약)` 금화 | 부족 물약 전량, HP·기력 최대 회복 | 1 |

수량은 작업 횟수다. 예를 들어 연금 물약 수량 5는 물약 15개다. 견적 코드의 음수 cost는 금화 보상이며 DB에서는 `gold_cost`와 `gold_reward`를 분리해 둘 다 0 이상으로 표현한다. 분해는 입력 장비 인스턴스의 등급·강화에 따라 달라진다.

기존 작업도 누락하지 않는다: 장비 구매·판매, 강화·재련, 길드 수락·보상, 여관 휴식. 관찰한 강화는 +5 상한, 비용 `(현재강화+1)*50` 금화와 광석 `현재강화+1`, 확정 성공이며 무기 기본 능력 +2/그 외 +1이다. 재련은 레어 이상, 80금화·정수1, 현재와 다른 옵션을 선택한다. 실제 옵션 후보와 확률은 Equipment 및 실행 함수를 기준으로 내보낸다. 길드 토벌은 목표10, 보상180금화·정수1, 휴식은10금화다.

신규 작업은 `handles()`의 라우팅이 우선한다. quote/transact의 뒤쪽에 남아 있는 기존 동일 이름 분기를 별도 레시피로 중복 수록하지 않는다. 거래의 마을·근접 시설 조건, 입력 검증, 모든 결과물이 들어갈 때만 상태 반영하는 원자성도 계약에 포함한다. 재료 소비/분해로 비워진 공간을 적용한 뒤 출력 수용 여부를 판단해야 한다.

## 던전·스킬

`dungeon.gd`에서 확인한 6개 ID: branching, circuit, great_cavern, side_hollows, split_bridges, crossed_halls. 38×38 공간, 앵커9개, 입구0·수문장8. 레이아웃 선택은 층·seed와 LAYOUTS 순서에 의존하므로 정렬해 순서를 잃지 않는다. 회전/반전0~7, 앵커 흔들림, 방 형태·반경, 통로 half_width=2(5칸), 대동굴 확장 규칙을 분리한다.

일반 방1~7의 수량 후보는 `[2,4,2,3,4,2,4]`, `[4,2,3,2,4,4,2]`, `[2,3,4,4,2,3,3]`이며 각각 합계21이다. 엘리트1·수문장1이 추가된다. branching/side_hollows는 엘리트 방3, 그 외6. formation0~3, mob_index의 층 보정과 실제 몬스터 ID 해석까지 연결해야 한다. 기존 appearances는 출현 가능한 조합이므로 생성된 개체 수와 혼동하지 않는다. seed별 좌표는 예시 스냅샷으로 분리하고 일반 카탈로그의 고정 출현 위치로 표시하지 않는다.

`skill_reach.gd`는 실제 반경 정책이다. 기존 skill_ranks.profile에 반경·사거리·판정 형태·단위를 확인하고 없으면 확장한다. job_balance/skill_scaling에서 이미 적용한 배율을 DB에서 재적용하지 않는다. 원형 반경, 부채꼴, 투사체 사거리와 표시용 VFX 크기를 구분한다. 피해·자원·무력화 예산 변화 여부도 별도로 검증한다.

## 아직 확정하지 않을 항목

- 조사 시 `training_ground.gd`는 아직 없었다. 수련장은 설계 상태로 기록한다. 표적 ID·HP/방어·무력화·자동복구, 측정 시작/종료/초기화, DPS 시간 분모·총 피해·타수·치명타 정의, 소환·지속피해 귀속, 드랍/XP/금화/퀘스트 진행 금지 여부를 최종 구현으로 확인한다.
- 독립 costume 시설은 기존 외형 소유·구매·착용 ID를 유지하고 시설 연결만 추가하는 계약을 권장한다. 가격·재구매·장착 조건은 최종 코드에서 읽는다.
- 가방120칸은 구현 예정이다. 조사 당시 WIDTH=10, HEIGHT=6이므로 현재120으로 수록하지 않는다. 물약 MAX_POTIONS=20도 인계 시 다시 읽는다.
- 허수아비와 시설 아트는 V0.5.1 art_sources/art_files/art_assets/art_uses를 따른다. 새 소유 테이블 연결 시 registry의 OWNER_TABLES/FK 검증을 확장한다. 준비 RGBA와 실제 사용 원본·런타임 파일을 혼합하지 않는다.

## 인계 및 검증 계약

구현 담당자는 최종 브랜치·commit(미커밋 변경이 있으면 파일별 SHA-256 포함), DB schema_version, 생성 명령과 검사 결과, JSON/SQLite/schema/manifest의 파일별 SHA-256을 전달한다. 새 서비스/수련장/인벤토리/던전/스킬 규칙 원본도 metadata.source_sha256 의존성에 포함해야 한다. release 표기만으로 스냅샷 일치를 판단하지 않는다.

관리권 인수 후 검사: PK/FK와 ID 중복, 금화·수량 범위, 수량별 견적/실거래 일치, 재료 부족·가방 부족 시 무변경, 분해 후 공간 확보, 물약 상한, 보상 이중수령, 장비 옵션 제외 규칙, 수련장 보상과 의뢰 진행 차단, 같은 seed 재현과 통로 연결, 스킬 실제 범위 일치. 기존 `python tools/build_database.py --check`와 관련 회귀 검사를 최종 원본에서 실행한다. 지금은 실행하지 않았다.

현재 완료 범위는 읽기 조사와 계약안 작성이다. DB 확장·재생성·검증 완료를 의미하지 않는다.
