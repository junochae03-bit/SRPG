# 오브젝트 크기와 플레이어 가림 보완

2026-09-13. QA팀을 통해 전달된 사용자의 오브젝트 크기·육중한 몬스터 크기 요청을 반영했다. 새 6등급 크기 비교와 종별 등급 배정은 별도 설계이며 이 변경에 자동 적용하지 않는다.

## 종류별 비율

픽셀 값은 카메라 확대 전 논리 화면 기준이다. 화면 배율이나 스프라이트의 투명 여백에 따라 최종 화면의 외곽 높이와 다를 수 있다.

| 지면 유해 | 표시 폭 |
|---|---:|
| 해골 | 100–116 |
| 갈비뼈 | 156–180 |
| 동굴 도마뱀 유해 | 148–172 |
| 딱정벌레 껍질 | 136–160 |

광석·낙엽 등 작은 흔적은 종류별 48–76 폭의 파편 군집으로 조정했다. 광맥·수풀·상자의 완성 형태를 반복하지 않는다. 유해는 커진 영역의 모서리·변 중앙·중심 9점을 실제 바닥에 투영하고 중심과의 연결까지 검사한다. 기능 장소·봉인과 5칸, 탐사 흔적과 4.5칸 이상 떨어지며 최대 5곳 제한을 유지한다. 180개 일반층의 최종 배치는 772개로, 이전보다 늘지 않았다.

캐릭터 몸통 높이 112를 기준으로 동굴 오크 180, 오크 도끼병 184, 태엽 경비병 172, 오크 투사 240, 기계 백인대장 236을 사용한다. 테마 원화가 바뀌는 경우 실제 생물별 설정을 사용하며 같은 원화도 일반과 정예를 구분한다. 예를 들어 주조장 철거수는 일반 188·정예 248이다. 보스 335는 유지한다. 작은 동물·날렵한 종은 그대로 둔다.

원화의 머리·어깨·발 위치와 이미 보정된 `body_height`를 확인하고, 원화 여백이나 무기 끝 때문에 몸통 크기가 달라지지 않도록 기존 보정 경로를 사용했다. 표시 높이와 피격 반경은 같은 종류·층 정보로 계산한다. 실제 렌더 사각형을 사용하는 마우스 선택도 유지한다. HP·공격력·공격 범위·적 수는 변경하지 않는다.

## 큰 몬스터 뒤의 플레이어

깊이 정렬에서 로컬 플레이어 앞에 그려지는 몬스터가 몸통·발 영역을 가리면 해당 몬스터의 불투명도를 42%로 낮춘다. 기존 몬스터가 들어오고 나갈 때는 약 0.12초에 걸쳐 변화하며, 새로 등장한 가림은 즉시 낮춘다. 몬스터의 체력바·전조·선택·피격 판정에는 투명도를 적용하지 않는다. 맵 이동 때 상태를 초기화한다.

QA가 지적한 B62·시드 491549의 같은 위치에서 불투명 대조와 최종 처리를 비교했다. 일반/정예 구분 보완 후 일반 기계 몬스터 높이 188인 현재 장면의 비교다. 최초 248 크기의 장면을 그대로 재현했다고 주장하지 않는다. QA팀은 현재 장면에서 플레이어 몸통·발과 공격 경계가 다시 식별되는 것을 확인했다.

## 확인과 인계

- 초기 자연동굴 정리 `cd8e780`은 필수 검사 152개 그룹을 분할 실행해 통과했다.
- 그 뒤 크기·피격·가림 변경에는 관련 모델·실제 선택/공격·전조·시야·HUD·UI 성능·DB 검사를 실행했다. 초기 전체 검사가 최종 크기 변경까지 전부 재실행된 것처럼 합산하지 않는다.
- 크기 전후 화면은 같은 최종 배치와 카메라에서 이전 폭을 대조한 화면이다. 정적 비교용 fixture이며 실제 이동 공격 AI나 사람의 장시간 혼전 플레이를 검증한 영상은 아니다.
- 새 6등급 배정, 일반 몬스터 40종 확장, 능력치·제작 설계는 별도로 남아 있다. 기존 미완료 벤치마킹 항목의 상태를 올리지 않는다.

관리 DB에는 유해/흔적의 종류별 폭, 몬스터 일반·정예 높이와 층별 출현 표시 높이, 유해 바닥 범위 검사 및 플레이어 가림 규칙을 등록했다. 정확한 실행 범위·화면 해시·정본 해시는 [검증 기록](qa/scene-scale-verification.json)에 보관한다.

DB 관리의 후속 전달로 0.5/1.2/2/3/6/10배 기준과 종 92개·레이드 ID 10개의 크기 배정 설계를 접수했다. 이 설계의 레이드 우선 규칙과 정예 자동 추가 확대 없음은 이후 적용 기준이며, 이번 런타임 변경에 섞지 않았다. 최종 크기/가림 정본도 DB 관리에 전달했으며 이 기록 시점의 독립 재검수 응답은 대기 중이다.
