# V0.5.3 플레이 완성도 작업

사용자 요청: 우선순위 1~7 전체 실행. 기존 온라인 전환은 보류하고 싱글 플레이를 기준으로 한다. 중심 구간은 캐릭터 생성·튜토리얼·마을·1~10층·첫 보스이며 기존 100층 콘텐츠의 호환성을 유지한다. 새 콘텐츠 수 늘리기, V06 원화 일괄 편입, 원본 추출 보관본 삭제는 범위 밖이다. 스텔알피지 제목은 기존 픽셀 글꼴을 유지한다. 개인 저장은 보존한다.

검증 자료는 runtime 및 artifacts에 두고 공개 소스에는 선별된 요약만 포함한다. DB 관리는 데이터 정합성과 성장/보상 분석, QA팀은 코드 및 경험 증거를 검토한다. 메인은 통합·플레이·UI·전투·성능을 담당한다. 엔진을 사용하는 작업은 조율하며 같은 파일을 동시에 수정하지 않는다. 아래 체크포인트는 QA 검토이며 별도 사용자 승인은 요구하지 않는다.

## 순서와 완료 기준

2026-09-10 인수 변경: 아래 1~7의 코드·데이터 개선과 최종 소스 393,026개 검사, 실제 EXE·저장 복사·Compatibility 검증을 통과했다. 사용자가 직접 플레이하고 피드백하기로 했으므로 첫 30분/연속 60분 자동 플레이는 중단하며 릴리스 조건에서 제외한다. 원래 계획의 장시간·주관적 평가 항목은 통과로 소급하지 않는다. 최종 근거는 `COMPLETENESS_V053.ko.md`를 따른다.

1. [구현·검증 완료] 최신 소스/DB/클라이언트 통합: 작명·역할 분류·밸런스·타이틀 변경을 확인하고 V0.5.3 기준 버전을 만든다. `python tools/build_database.py --check`, `python tools/verify_v01.py`, 배포 도구의 현재 명령을 확인해 실행한다. 기준 빌드 SHA256과 실제 화면을 기록하고 QA에 전달한다.
2. [개선 반영·플레이 평가 사용자 인수] 첫 30분: 검사·궁수·마법사 새 기록으로 정상 진행 경로를 확인한다. 목표·첫 장비·첫 투자·마을 진입·첫 던전·실패 복귀에 생긴 마찰을 기록하고 관련 UI/진행 코드만 수정한다. 30분 실제 관찰과 신규 사용자 이해도는 구분한다. 실행 도구는 조사 후 여기에 명령을 확정한다.
3. [개선 반영·플레이 평가 사용자 인수] 전투: 일반·정예·보스전의 적 예고, 타격 시점/범위, 회피, 경직, 음향을 실제 화면과 공격 이벤트에 대조한다. 기존 combat/monster_aim/skill_reach 회귀 및 실전 비교를 수행한다. 발견 문제만 수정하고 조건과 전후 증거를 QA에 전달한다.
4. [개선 반영·플레이 평가 사용자 인수] 스킬 선택: 네 역할의 모양·연결·대상 액티브·투자 전후를 UI에서 구분한다. 긴 이름, 선택/잠금/학습 상태 및 6개 장착 슬롯을 확인한다. `python tools/run_hidden_check.py skill_tree_ui_v04 graphics`, 분류 및 모듈 격리 검사를 실행한다.
5. [개선 반영·플레이 평가 사용자 인수] 던전 경험: 1~10층 중 대표 세 구간에서 배치·지형·진입 안전·위험 요소가 다른 선택을 만드는지 확인한다. 같은 조건의 두 빌드로 적 AI를 켜고 실제 교전을 비교한다. `dungeon_variety_v052`, `dungeon_entry_v04` 및 실전 기록을 사용한다.
6. [개선 반영·플레이 평가 사용자 인수] 성장/보상: 정상 진행의 레벨/장비/강화 간격, 소비 재화와 복귀 동기를 측정하고 DB 관리의 분석과 합쳐 조정한다. 기존 ID와 개인 기록 호환을 유지한다. DB 재생성/검사 및 장비·드랍·진행 회귀를 통과한다.
7. [개선 반영·플레이 평가 사용자 인수] UI/성능 마감: 공통 글자·아이콘·버튼 상태와 도감 첫 열기를 점검한다. 1920×1080 실제 창에서 60분 연속 실행하며 이동·전투·메뉴·마을·저장·재진입의 프레임 분포와 메모리 추세를 기록한다. 짧은 벤치마크 반복으로 대신하지 않는다. 최종 전체 소스 및 EXE 검증, QA·DB 인수 후 커밋·병합·푸시하고 D:\SRPG에 필요한 실행 파일만 갱신한다.

## 진행 기록

- 시작 시 main 정본 8daddbd. 미커밋 작명·밸런스 변경과 타이틀 메뉴 변경 존재. V06 별도 원화는 미추적 상태이며 보존한다.
- 기존 제품 보수 계획의 첫 30분/실전 빌드 차이/60분 성능은 완료 근거가 없으므로 이번에 새로 수행한다.
- 통합 전 기준 전체 회귀 387,921개 통과. 이후 변경 사항은 다시 전체 검증한다. 기준 PCK와 최종 PCK를 혼용하지 않는다.
- 첫 튜토리얼 완료 시 LV.2까지 부족한 경험치를 지급하고 일반 레벨업 경로로 SP/능력치를 받는다. 초반 일반 드랍의 장비 단계 제한을 바로잡고 여관에 물약 5개 보급을 추가했다. 관련 회귀 1,197개 통과.
- 평타/강공격 해제 포즈를 타격·발사 단계에 맞추고, 유효 피격 표적에 짧은 반응을 추가했다. 캡슐 공격 끝과 고리 내부 안전 구간을 판정에 맞춰 그린다. 전투 회귀 193개 통과. 실제 음향 청취와 연속 애니메이션의 미술 판정은 별도다.
- 스킬 지도에 사용 기술/기술 강화/행동 변화/능력치의 모양·필터를 구분하고, 모듈의 대상 기술 연결을 표시했다. 20직업 화면과 배지·글자 간격 회귀 12,230개 통과.
- 같은 LV.10/9SP/장비의 두 빌드로 B6/7/8 및 3개 시드를 비교했다. 18개 시나리오에서 AI와 판정이 켜진 상태로 전투했다. 12처치까지만 측정하므로 장기 보스전·승률 근거로 쓰지 않는다.
- 빈 화면까지 30FPS가 유지되는 OpenGL 경로 문제를 분리했다. 이 PC의 Vulkan Mobile 실제 게임 60초에서는 p95 19.592ms/p99 22.789ms를 측정했다. 기본 렌더러를 변경했고 장시간 배포 검증은 별도로 진행한다.
- 검증된 바이너리 도감 캐시와 시작 시 준비를 추가했다. cold snapshot의 직업 정의 초기화 누락을 전체 검사에서 발견해 수정, DB 5,305개/캐시 909개 통과. 캐시는 원본에서 재생성하며 손상되면 실시간 생성으로 돌아간다.
- `tools/run_playtest_v053.py --exe <StelRPG.exe> --seconds 3600 --class-id warrior`는 실제 배포 EXE를 직접 실행한다. 신규 테스트 저장을 별도 폴더에 만들고 정상 행동·거래만 사용한다. `tools/analyze_playtest_v053.py <관찰 폴더>`로 프레임·메모리·멈춤 근거를 집계한다. source 모드는 EXE 검증으로 표시하지 않는다.
- 배포 진단 `warrior-20260910-142551`은 60분 완료 전에 중단했다. 실제 스킬 화면의 작은 역할/선행 배지에 전체 종이 프레임을 축소해 장식이 글자에 붙는 것을 발견했다. 배지는 테두리 장식을 제외한 기존 종이의 중앙 질감을 사용하도록 수정했다. 이 실행을 60분 통과 근거로 쓰지 않는다.
- 같은 진단에서 생성 동기 호출 중 28.148초 지연이 한 번 있었다. 앞선 동일 배포 30초 실행에서는 재현되지 않았다. CPU 소모·저장·GPU 원인으로 단정하지 않으며 미해결 지연으로 기록한다. 이후 계측은 직업 선택/이름 갱신/생성 제출 경계를 나눈다.
- 진단의 실제 저장에서 유니크 무기 +3 및 7부위 착용을 확인했다. 이전 강화 이벤트의 갱신 전 참조를 수정해 이제 거래 후 저장 상태의 강화 수치를 기록한다. 옵션 개방과 보스 상태도 별도로 기록한다.

## QA 보완 기준

- 기준 파일 목록/해시 및 새 명칭·역할 데이터/조회기/생성기/회귀의 등록을 확인한다. 저장 schema3/7 왕복·재정규화 멱등성을 확인한다.
- 첫 진행은 직업별 실제 관찰 시간을 기록한다. 자동 조작은 에이전트 관찰이며 신규 사용자 이해도 판정과 구분한다. 치트·임의 재화·레벨·좌표 변경 없이 플레이하고 미도달 이벤트는 미확인으로 남긴다.
- 전투는 예고→판정→시청각 반응 시각과 벽/회피/사망/리셋 경계를 기록한다. 실제 청취 없는 음향 품질을 통과라고 쓰지 않는다.
- 모듈은 대상/비대상 액티브·평타·지연효과를 분리 검사하고 미리보기와 실제 비용·피해·재사용 수치를 대조한다.
- 보상/밸런스 수정이 이전 결론에 영향을 주면 해당 진행·전투 경로를 재검증한다. 첫회·반복·희귀 보상을 구분한다.
- 최종 60분 성능 목표: 1920×1080, 60FPS 제한, 게임플레이 구간 p95 20ms 이하/p99 33.4ms 이하, 100ms 이상 멈춤은 모두 원인 분류. 초기 10분 준비 이후 마지막 10분까지 프로세스 메모리 증가 10% 이하를 목표로 하며 기준 미달을 숨기지 않는다. OS 포커스·설정·GPU·메모리 샘플 간격 기록. 연속 60분과 종료 후 재진입 검사는 분리한다.
