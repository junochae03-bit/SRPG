# 자유 탐사 던전 개발 인계

2026-09-12 개발본. 공개 배포·설치본 교체·릴리스는 수행하지 않았다. 기존 협동 및 스킬 사이드바 개발 변경 위에 이어진 작업이며 별도 V06 에셋 작업은 보존했다. 선택한 46개 벤치마크 전체 완료를 뜻하지 않는다.

## 반영 범위

- 일반층: 80×80 영역, 교차 회랑을 제외한 5종 순환 그래프. 기존보다 구역 간 거리를 1.6배로 늘리고 각 공동 반경을 2칸 확대했다. 여러 독립 순환 경로와 비대칭 곡선 연결, 최소 7칸 통로와 안전한 진입 공간을 유지한다. 레이드 전장은 기존 크기와 별도 구조를 유지하며 전체 길을 미니맵 안에 맞춘다.
- 레이드층: 매 10층에 일반층과 별도의 원형·대회랑·십자 성소 전장. 입구→휴식→보스 전장의 3구역이며 잡몹은 없다. 전장 중앙은 장애물 없이 넓게 확보하고 큰 배경 소품은 바깥에 둔다. 수문장 처치와 다음 층 해금은 유지한다.
- 일반층마다 채집방·중간 휴식·선택형 제단을 하나씩 배치한다. 방의 적과 근처 적을 정리한 뒤 이용한다. 레이드층에는 휴식 지점만 둔다.
- 채집: 별씨앗/광석 3+층 등급. 휴식: 생명력·기력 회복. 제단: 최대 생명력 35% 회복 또는 물약 1개를 정수 2+층 등급으로 교환, 둘 중 하나.
- 각자 한 번 이용하고 다른 동료의 선택을 소모하지 않는다. 보관 공간·묶음 한도·비용을 후보 상태에서 검사한 뒤 확정한다. 실패한 선택은 비용이나 청구 상태를 변경하지 않는다.
- 가까이 가면 결과와 비용이 있는 작은 선택 카드가 나타난다. 채집·휴식은 상호작용 키로도 이용한다. 제단의 두 선택은 버튼으로 구분하며 개인 선택창은 월드를 멈추지 않는다.
- 기존 광석·관목·화로·석조 수반 스프라이트를 기능 오브젝트로 사용한다. 꾸밈 소품을 무작정 추가하지 않는다. 이동 불가 영역은 지면 명암으로 구분한다.

## 협동과 저장

`explore` 요청은 `generation:room_id:choice`이고 generation은 생성 seed/zone/floor다. 방장이 현재 생성 식별자·거리·시야·주변 적·이용 여부·보관 한도·비용을 모두 판정한다. UI는 해당 generation과 실제 표시 이름·재료가 바뀌면 다시 그린다. 개인 청구는 본인에게만 snapshot으로 전달하며 기존 개인 checkpoint/퇴장 디스크 ACK를 사용한다. 저장된 재료 보상은 기존 자료형을 사용한다. 층 자체를 저장했다가 재개하는 기능은 이번 범위가 아니며 재실행은 기존처럼 마을에서 시작한다.

프로토콜은 2로 올렸다. 이전 개발본과 새 던전 규칙을 섞어서 접속하지 않는다.

## DB 관리

`tools/build_database.py`로 JSON·SQLite·준비된 도감 캐시를 재생성한다. 스키마는 5를 유지한다.

- `metadata.exploration_rules`: 방 종류·거리·위협·개인 청구·수량 규칙.
- `metadata.exploration_source_rules`: 런타임 실제 함수 11개와 경로/SHA. 생성 출현과 보스 추적의 원본 함수까지 포함한다.
- `metadata.raid_layouts`: 전용 전장 3종과 진입·휴식·보스 연결.
- `dungeon_layouts`: 일반층 6종의 좌표·반경·연결.
- `appearances`: 레이드층 잡몹 제거를 실제 출현 정보에 반영, 620→568행. 몬스터 정의 24개·레이드 10개·층 100개·장비 2500개·스킬 610개는 유지한다.

현재 생성 파일 SHA256:

- JSON: `cfb0dda1c86e544d9d8dfec57714b3c34c58d65b9bc41db19be41375ffdd265f`
- SQLite: `31e299c1183c7afb989db5902ab6a30274798424401851c4cf8208126801e280`
- manifest: `b851e812ce49e11d37a0a81c4ed9c359bb280fb0993b4c74411c9f29226a57b8`

## 검증 상태

- `exploration_rooms`: 2500개 검사 PASS. 보관 실패·개인 중복·택1 배제·거리·위협·이탈·과거 생성 요청 거절, 보스 전장 9칸 거리 추적 포함.
- `dungeon_variety_v052`: 300맵/105053개 검사 PASS. 모든 타일 연결, 방까지의 5칸 경로, 몬스터 위치, 레이드 전장, 기존 튜토리얼·마을 접근성.
- `run_coop_check.py`: 생성 식별자를 포함한 6개 독립 프로세스 RPC PASS. 각자 같은 채집방에서 수령하고 반복 요청해도 한 번만 지급된다. 기존 저장·종료 실패/재시도도 통과. 로그: `runtime/coop-check-1789211603235894900`.
- QA가 UI 캐시와 요청 세대 문제를 지적했고 수정 후 코드·모델 로그를 직접 읽어 해당 두 수정의 인수를 확인했다. 전체 게임 QA와 실제 친구들의 외부 접속 검증은 별개다.
- QA가 갱신된 8개 PNG와 모델·6인 RPC 로그를 직접 확인하고 새 차단 결함을 발견하지 않았다고 회신했다. 근접한 캐릭터명/시설명 겹침 지적도 받아 시설명의 월드 중복 표시를 제거했다. 정적 캡처·9칸 추적 검사와 실제 6인 전장 전체 실전은 구분한다.
- DB 관리가 최종 생성물의 원본 316개 SHA, 탐사 규칙 11개, JSON/SQLite metadata, 스키마5·무결성·외래키·manifest·STDB 정합성을 읽기 확인했고 위 최종 해시로 관리 기준을 갱신했다.
- `exploration_visual`: 39개 검사 PASS, 실제 1920×1080 캡처 8개. 같은 방 ID·같은 등급에서 숲→동굴 재료 표시 전환, 시설명을 캐릭터 이름 위에 중복하지 않는 것까지 확인했다.
- `dungeon_tactics_v053`: 18개 실제 AI 비교 시나리오/37개 검사 PASS. 적을 예고 종료 전에 처치하면 공격 발동 수가 0일 수 있으므로 실제 예고 또는 발동을 검사하고, 별도의 정지 대조군으로 실제 피격을 검증한다.
- 최종 전체 회귀: `tools/verify_v01.py` 105개 검사 그룹/403826개 검사 PASS. 한글·인코딩 411파일 오류 0. 런타임 347개 파일, 463.63MiB. 원본 저장 SHA 유지 및 복사본 마이그레이션/재시작 통과. 결과는 `artifacts/v01_verification.json`에 기록했다. 설치 도구 검사는 수행했으나 사용자의 설치본 교체·릴리스는 수행하지 않았다.

## 아직 남은 범위

탐사 목적/거래형 사건/채집/휴식/데이터 생성의 첫 단계다. 사건 종류 확장, 환경 규칙, 장비 정비가 있는 휴식, 준비 요약·귀환 보고, 시설 연구·제작 큐·창고, 외부 인터넷 협동 및 장시간 밸런스는 남아 있다. 사용자에게 선택 46개 전체 반영으로 보고하지 않는다.
