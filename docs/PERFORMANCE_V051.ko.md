# V0.5.1 성능 측정

마을·던전·메뉴에서 반복되던 이미지 배경색 제거와 UI 정보·배경 도형 계산을 줄였다. 같은 기존 기록으로 비교한 첫 월드 그리기 CPU 구간은 마을 1113.788 → 187.813ms, 던전 161.879 → 49.746ms였다.

| 항목 | V0.5 기준 | V0.5.1 |
|---|---:|---:|
| 마을 첫 월드 그리기 | 1113.788ms | 187.813ms |
| 마을 반복 HUD 처리 중앙값 | 0.739ms | 0.296ms |
| 마을 반복 월드 그리기 중앙값 | 1.351ms | 0.962ms |
| 던전 반복 월드 그리기 중앙값 | 2.018ms | 1.330ms |
| 41시트 CPU 변환 / 준비 파일 읽기 | 10810.360ms | 658.172ms |
| 동일 152개 장식의 도형 계산 | 384.522µs | 69.744µs |

41시트는 기존 RGBA와 모든 바이트가 같음을 검사했다. 픽셀 비교의 마지막 두 시간은 headless CPU 처리이며 GPU 업로드 속도 측정이 아니다. 배경은 별도로 102개 맵에서 원래 배치의 55.18%를 남기고 108종의 그림·위치·크기·알파 동작을 보존했다.

수정본의 첫 가방 열기는 약 69ms, 스킬 화면은 72ms였다. **도감 첫 구성에는 약 0.73초가 남는다.** 현재 플레이 기록의 별도 복사본에서도 마을·가방·스킬·봇 전투를 확인했다. 각 경우는 12초이며 원본 저장을 수정하지 않았다.

측정 환경은 Windows, Godot 4.6, OpenGL Compatibility, RTX 4070 SUPER다. 최종 측정은 실제 키·마우스 입력이 메뉴를 바꾸지 않도록 차단하고, 정지한 캐릭터 또는 검사 봇으로 진행했다. 비교 대상은 월드·HUD CPU 구간이며 프로브가 대체한 입력 처리 시간은 비교하지 않는다. 창에 요청한 해상도는 프로젝트 기본값이며 실제 창 크기와 논리 뷰포트 크기를 [측정 JSON](PERFORMANCE_V051.json)에 함께 남겼다. UI 픽셀 검사는 별도로 1920×1080을 고정한다.

숨겨진 창의 프레임 간격은 포커스·GPU 스케줄링에 따라 변하므로 실제 플레이 FPS로 환산하지 않는다. 각 수치는 단일 실행이며 모든 장치에서 같은 개선율을 보장하지 않는다.

재현: `python tools/profile_client.py --save <저장 JSON> --label check-town`, `--floor 1`, `--menu bag`, `--menu skills`, `--menu codex`, `--floor 1 --combat`. 저장 JSON은 자동으로 격리된 검사 폴더에 복사한다. `GODOT_EXE`에 Godot 4.6 경로를 지정한다.
