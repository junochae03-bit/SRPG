# 소지품과 상태에 반응하는 탐사 사건

2026-09-13. E02의 사건 선택을 기존 선택 방에 연결한다. 맵 면적, 방 수, 탐사 지점 수를 늘리지 않고 보급 상자와 제단을 변형한다. 같은 생성 시드에서는 파티 모두 같은 장소와 사건을 만나며, 각자의 현재 상태로 선택하고 보상을 받는다.

| 발견 | 선택 1 | 선택 2 |
| --- | --- | --- |
| 약초 그루터기 | 별씨앗 2개로 물약 3개 조제 | 별씨앗 3+단계개 채집 |
| 잠긴 보급 상자 | 탐사 도구 1개로 정수 5+단계개 회수 | 광석 2+단계개 회수 |
| 생명의 제단 | 최대 생명력의 20%를 바치고 정수 4+단계개 획득 | 최대 생명력의 30%만큼 회복 |
| 메아리의 등불 | 기력 40으로 정수 3+단계개 획득 | 최대 기력의 60%만큼 회복 |

단계는 기존 10층 구간의 `floor((floor-1)/10)`이다. 생명력 비용은 올림하고 최소 1이며, 비용과 현재 생명력이 같거나 현재 생명력이 더 적으면 거절한다. 회복량은 부족한 양까지만 적용한다. 생명력이 가득 찼거나 기력이 가득 찼을 때 해당 회복은 소비되지 않는다. 제단 비용은 전투 피격으로 처리하지 않는다.

보급·제단은 각각 기존 장소 1종과 새 변형 2종 중 같은 비중으로 선택한다. 독립 난수 시드 `map.seed_value + 103331 + site.room * 193`를 사용한다. 레이드에는 기존 휴식 장소만 남긴다. 단서는 약초·쇠장식·붉은 흔적·울리는 소리로 구분하며, 기존 단서 2개를 교체해 장식을 추가하지 않는다.

## 조작과 표시

가까이 접근하면 기존 비모달 패널에 장소 이름, 현재 소지량 또는 생명력·기력, 두 선택의 비용과 결과가 나타난다. 파티에서는 `각자 택 1`로 표시한다. 현재 비용을 낼 수 없거나 보상을 담을 수 없으면 해당 버튼을 비활성화하고 이유를 툴팁으로 연결한다. 선택을 마치면 자신의 패널만 닫힌다. 같은 장소에서 동료는 다른 선택을 할 수 있다.

UI는 현재 개인 상태를 읽어 견적을 갱신한다. 네트워크 스냅샷에는 사건의 공개 정의와 해당 플레이어의 이용 여부만 들어가고 견적 계산용 복사 인벤토리는 보내지 않는다. 선택 화면을 열어도 협동 전투 시간은 진행된다.

기존 그루터기·결박된 상자·제단·등불 그림을 재사용한다. QA가 처음 지적한 조제대/불타는 수레의 명칭·외형 불일치는 그루터기 명칭 변경과 닫힌 상자 교체로 해소했다. 그림 안에 기능을 설명하는 장식이나 새 안내 문단을 추가하지 않았다.

## 판정과 소유권

`exploration_rooms.gd`가 호스트 지도에서 생성 식별자, 지점 ID, 허용 행동, 거리, 시선, 생존, 이탈 상태, 주변 적, 기존 개인 이용 기록을 검사한다. 이후 `exploration_events.gd`가 현재 소유 상태를 깊은 복사하여 비용과 보상을 모두 계산한다. 모든 조건을 통과한 경우에만 실제 생명력·기력·물약·재료·가방 위치와 개인 이용 기록을 변경한다.

- 비용 부족, 보상 수량 한도, 가방 공간 부족은 비용이나 이용 기록을 남기지 않는다.
- 마지막 재료를 전부 소모해 가방 칸이 생기면 그 칸에 결과물을 받을 수 있다.
- 재료가 남아 결과물을 담을 칸이 없으면 거래 전체를 취소한다.
- 같은 요청 재전송, 같은 선택 재시도, 이후 다른 선택으로 바꾸기는 추가 보상을 주지 않는다.
- 실패한 선택 뒤에 다른 선택을 고를 수 있다. 동료의 선택·재료에는 영향이 없다.
- 획득품은 기존 개인 저장을 사용하고, 이용 기록은 생성된 층 동안 유지한다. 다음 층의 새 장소는 다시 이용할 수 있다.

협동 프로토콜은 9, 저장 형식은 7이다. 원정 중 재접속과 개별 귀환은 여전히 별도 미완료 항목이며, 이 변경의 개인 저장 검사를 원정 복원 완료로 세지 않는다.

## DB와 검증 근거

정본에는 `metadata.exploration_events` 및 `metadata.exploration_event_source_rules`를 추가했다. 정의와 수식뿐 아니라 `select`, `choices`, `quote`, `describe`, `detail`, `use`의 실제 함수 원본과 해시를 보관한다. JSON·SQLite·도감 캐시·런타임 목록은 기존 생성기로 만든다. 별도 수작업 DB나 원화 묶음을 추가하지 않는다.

모델은 100층의 결정적 생성, 4종 출현, 비용/회복, 개인 선택, 중복/이탈/거리/이전 층 요청, 수량 한도, 실제 120칸 가방 경계를 검사한다. 실제 화면은 4종의 선택 가능·비용 부족 상태 8장을 캡처하고 제목·버튼·개인 선택 표시와 실제 클릭 결과를 확인한다. 그림 확인을 위해 시각 테스트는 전투를 정지시킨다.

실제 6인 ENet에서는 재료가 있는 호스트만 조제하고 재료가 없는 동료 5명은 실패한 뒤 각자 채집을 선택한다. 각 선택을 중복 전송해도 비용과 보상이 1회만 적용되고, 기존 전진 지름길·공유 도전·개인 보상·퇴장 저장 검사를 함께 실행한다. 최종 결과는 `docs/qa/exploration-events-verification.json`에 보관한다.

네 가지 사건만으로 전체 탐사 재미나 모든 벤치마킹이 완성됐다고 판단하지 않는다. 사건의 반복 체감·경제와 직업별 효율은 장기 플레이 평가가 필요하며, 마을 해금·연구·보급·의뢰 결과에 연결하는 후속 작업이 남아 있다.
